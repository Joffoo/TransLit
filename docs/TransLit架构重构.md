# TransLit 架构重构笔记

---

## 一、 背景与重构动机

在我的上一个版本的 AI 翻译流水线中，通常采用“**暴力转换**”策略：使用 `turndown` 直接将整本 EPUB 的网页文件（XHTML）转换为纯文本 Markdown，再按固定字数机械切片发送给大模型。

这种模式在面对严肃出版物或学术书籍时，暴露出 **3 个致命痛点**：
1. **跨文件链接断裂**：许多出版级图书的注脚存放在独立的 `notes.xhtml` 中，转为 Markdown 后，跨文件链接完全丢失或退化为不可点击的纯文本。
2. **切片导致的注脚脱节与术语失真**：当一个长章节被切成多个 Chunk 时，前序切片仅包含角标（`[^1]`），后序切片仅包含解释。模型在翻译前序正文时缺乏背景信息，导致术语误译；同时直接暴露 Markdown 注脚语法容易诱发模型幻觉，误删或篡改角标编号。
3. **缺乏现代移动端交互体验**：传统输出在章节末尾追加简单的列表，读者点击后发生大幅度页面跳转；而在 Apple Books、微信读书等现代阅读器中，读者更期待即点即看的**同页原生悬浮气泡**。

为了解决上述问题，TransLit 进行了深层架构重构：**彻底移除对外部 AI 前置清洗脚本的依赖，在前端运行时构建一条基于纯算法（DOM/AST 解析）的确定性流水线。**

---

## 二、 核心重构方案：四大算法支柱

```
EPUB XHTML 解包
       │
       ▼
【支柱 1】全书拓扑扫描与注脚同页内化 (FootnoteResolver)
       │  • 0-Offset 占位保护原书结构与目录
       │
       ▼
【支柱 2】双阶页面智能分类器 (Two-Stage PageClassifier)
       │  • 阶梯一：本地硬规则 (毫秒级预判)
       │  • 阶梯二：轻量 AI 裁判 (仅用于过渡页)
       │
       ▼
【支柱 3】保险箱插槽与双通道上下文切片 (FootnotePool)
       │  • 角标替换为不可变占位符 (__FN_REF_{id}__)
       │  • [MAIN_CONTENT] 与 [FOOTNOTES_TO_TRANSLATE] 同车发送
       │
       ▼
【支柱 4】EPUB 3 原生弹注与无害增量样式挂载 (EpubService)
       │  • 生成 <aside epub:type="footnote"> 原生气泡
       │  • 样式精准靶向挂载，100% 保持原书排版风格
       │
       ▼
打包导出标准 EPUB 3 电子书
```

---

### 支柱 1：跨文件拓扑索引与注脚同页内化

* **绘制全书雷达地图**：
  在图书解包阶段，程序遍历所有 XHTML 文件，精确定位全书所有带 `id` 且具备注脚特征的 DOM 节点（如 `<li id="fn1">`），在内存中建立唯一的全局映射索引：`Map<文件路径#原始ID, 注脚内容>`。
* **章节命名空间内化（把客人请进屋）**：
  当扫描正文章节时，程序自动识别指向外部注脚文件的超链接，将远端注脚内容直接克隆收录到当前章节的数据包中，并赋予带有章节序号的独立身份证（例如：`#fn-1-1` 表示第 1 章第 1 条注脚）。这彻底杜绝了不同章节注脚编号重叠导致的冲突。
* **零位移安全占位（0-Offset）**：
  被抽空的 `notes.xhtml` 绝不物理删除，否则会导致全书清单（`content.opf`）和目录（`toc.ncx`）出现死链而损坏电子书结构。系统会在原位置写入一个友好占位页：“*本书注释已自动内化至正文，点击角标即可直接弹出*”，实现 100% 结构闭环。

---

### 支柱 2：双阶页面智能分类（本地规则 + 轻量 AI）

为了给用户提供精准的“**翻译 / 剔除 / 保留原文**”推荐，系统采用漏斗式两阶决策，拒绝盲目调用 AI：

1. **阶梯一：本地硬规则（0 毫秒、0 费用、100% 确定性）**
   * **已内化注脚源**：标记为系统占位，锁定保护，防止用户误剔除导致全书注脚丢失；
   * **纯图片/封面页**：仅包含媒体标签且正文字数少于 30 ➔ 推荐【保留原文】；
   * **目录导航页**：包含 `<nav epub:type="toc">` 或主要由跳转链接构成 ➔ 推荐【跳过翻译】；
   * **版权页 / 出版社推广页**：命中 `ISBN`、`Copyright` 或订阅链接 ➔ 推荐【剔除】；
   * **长篇正文章节**：正文结构完整且达到字数阈值 ➔ 推荐【翻译】。
2. **阶梯二：轻量 AI 裁判（仅针对灰色地带）**
   * 仅当遇到字数较少、规则难以断定的过渡页（如短献词、推荐序、附录）时才异步触发；
   * 发送极简信息包（`{ 标题, 总字数, 前200字剪影 }`），耗费极低 Token 快速定性；
   * **权限解耦**：AI 输出仅作为界面的预勾选建议，最终决定权完全归还给用户。

---

### 支柱 3：保险箱插槽与双通道上下文感知切片

为了彻底杜绝模型对 Markdown 注脚语法的幻觉与篡改，系统重构了切片流水线：

1. **角标不透明占位符（Opaque Slotting）**：
   在送交模型前，程序把正文中的角标临时封入“不可变保险箱”：`__FN_REF_28-1__`。提示词硬性约束模型原样搬运，彻底杜绝角标被删或变异为普通文本。
2. **双通道同车护送（Dual-Channel Payload）**：
   切片器识别段落级引用关系，将正文与关联的注脚原文拼接在同一请求中：
   ```text
   [MAIN_CONTENT]
   正文段落包含 __FN_REF_28-1__ 占位符...
   [/MAIN_CONTENT]

   [FOOTNOTES_TO_TRANSLATE]
   [FN_DEF:28-1] 注释的英文具体释义... [/FN_DEF]
   [/FOOTNOTES_TO_TRANSLATE]
   ```
   大模型既能参考注释精准理解正文术语，又能同步产出注释译文。
3. **全局翻译缓存池与位置容错**：
   已翻译过的注脚被缓存到全书注脚池中，后序切片若再次引用，自动作为只读参考注入，避免重复计费与译文不一致；解析端支持**四级弹性匹配**（命名空间 ID ➔ 自然数字 ➔ 切片内出现顺位 ➔ 模糊正则），即使模型重新按 1 编号或输出全角中文标点，程序也能精准归位。

---

### 支柱 4：EPUB 3 原生弹出式注脚与无害增量样式挂载

1. **EPUB 3 原生 Aside 弹注语义**：
   翻译拼合完成后，程序舍弃传统的文末列表，将正文角标渲染为标准引用，并在章节底部生成标准的 EPUB 3 弹窗容器：
   * 正文角标：`<a id="fnref-1-1" href="#fn-1-1" epub:type="noteref" class="noteref"><sup>[1]</sup></a>`
   * 弹注容器：`<aside id="fn-1-1" epub:type="footnote" class="footnote-popup">`
   Apple Books、微信读书等现代阅读器识别到该标准后，会自动激活原地浮窗气泡。
2. **样式“无害增量挂载”（Add-on Injection）**：
   * **不破坏原书风貌**：系统绝不整体替换原书的 CSS，而是精准找到原书的主样式表，仅在文件最末尾追加专属于新组件的补充规则（`.footnote-popup`、`.noteref` 等）；
   * **特异性隔离（井水不犯河水）**：由于追加的规则全部使用专用类名，原书的正文、标题、引文等通用标签完全不受干扰；
   * **优雅降级**：在支持弹窗的阅读器中呈现悬浮气泡；在老旧阅读器中自动作为文末带虚线分隔的补充注释呈现。

---

## 三、 重构收益与成效

1. **确定性质量**：算法取代 Prompt 猜测，消除了因模型幻觉导致的注脚丢失、角标错乱和死链。
2. **断点续传与持久化完备**：切片级增量写入本地 IndexedDB，页面刷新或网络重试后注脚与上下文池完好无损。
3. **出版级阅读体验**：输出的书籍完全符合 EPUB 3 国际标准，主流移动端阅读器均可享受免跳转的点击即弹气泡交互。
